# 朗讀（tts.js）說明

## 語音怎麼選
- 朗讀用的是瀏覽器內建的語音（Web Speech API），聲音來自這台裝置或瀏覽器，網站本身沒有聲音檔。
- 自動選語音的順序：上次在語音選單選過的 → 臺灣國語語音 → 其他中文語音。
  - 臺灣國語語音的判斷：語言碼 `zh-TW`、`zh_TW`、`zh-Hant-TW`、`cmn-TW`、`cmn-Hant-TW`，或名稱是已知的臺灣語音（Google 國語（臺灣）、美佳 Meijia、HsiaoChen 曉臻、HsiaoYu 曉雨、YunJhe 雲哲、Hanhan 涵涵、Yating 雅婷、Zhiwei 志瑋）。
  - 同時有好幾個臺灣語音時：Google → 微軟線上自然語音（Edge）→ 增強版／高音質 → 美佳 → 其他。
- 有些瀏覽器（iPhone Safari、Android）頁面剛打開時語音清單還是空的，晚一點才送來。清單送來時會重新挑一次；如果朗讀已經開始、而且用的不是臺灣語音，會換成臺灣語音，從目前這句重唸。
- 朗讀時，上方 ▶ 朗讀旁邊有語速（1×／1.25×／1.5×）、性別（女／男）、地區（臺／陸／港）。某一種語音這台裝置沒有就隱藏該按鈕。選過會記住（`localStorage`：`reader.ttsRate`、`reader.ttsGender`、`reader.ttsRegion`、`reader.ttsVoice`）。換性別或地區若正在唸，會用新語音重唸目前這句。
- 只聽到大陸口音、選單裡也沒有「臺灣國語」這一組，代表這台裝置沒有裝臺灣語音。照下面的方法加裝，裝好後關掉瀏覽器再開。

## 加裝臺灣國語語音
- iPhone／iPad：設定 → 輔助使用 → 朗讀內容 → 聲音 → 中文 → 中文（台灣）→ 美佳。選「美佳（增強版）」可以下載品質較好的版本。裝好後 Safari、Chrome 都會用到。
- Mac：系統設定 → 輔助使用 → 朗讀內容 → 系統聲音 → 管理聲音… → 中文（台灣）→ 勾選「美佳」。用 Chrome 的話，連網時另外還有「Google 國語（臺灣）」可選。
- Windows 10／11：設定 → 時間與語言 → 語言與地區 → 新增語言 → 中文（台灣），安裝時勾選「文字轉語音」。裝好會有 Hanhan、Yating、Zhiwei。用 Edge 的話，連網時另外有 HsiaoChen、HsiaoYu、YunJhe 等自然語音。
- Android：設定 → 系統 → 語言與輸入 → 文字轉語音輸出 → 偏好的引擎選「Google 語音服務」→ 齒輪 → 安裝語音資料 → 中文（台灣）。Samsung 手機的路徑是 設定 → 一般管理 → 文字轉語音；如果預設是 Samsung TTS，可改成 Google 語音服務再安裝。各品牌選單名稱略有不同。

## 讀音
- 畫面上的經文不變，只有給語音唸的字會換掉（`books/<id>.tts.json`），讓語音照注音唸、注音符號不會被唸出來。
- 全部破音字的檢查表：`polyphones_review.csv`／`.md`（`tools/polyphones.py` 產生，不放在網站上）。

### 換字規則：破音字一律換（River 2026-11-20 起）
- 以前是「預測語音會唸錯才換」，結果「淺」「幢」這種預測沒抓到的字還是唸錯。現在改成決定式（`tools/tts_subs.py`）：
  書裡每一個破音字（教育部注音表有兩個以上讀音、注音不是它平常的讀音，或臺灣與大陸的預設讀音不同），每一處都換成
  「只有一個讀音、就是注音那個讀音」的常用同音字。例：觀 ㄍㄨㄢ→官、為 ㄨㄟˋ→位、相 ㄒㄧㄤˋ→向、無 ㄇㄛˊ→魔、菩→葡、得→德。
  只有一個讀音的字照原字唸。
- 同音字怎麼挑：Big5 常用字、jieba 字頻 ≥ 200（≥ 1000 的優先），教育部注音表和 pypinyin 都只有這一個讀音的最好；
  其次是教育部只列一個讀音、pypinyin 雖列別的讀音但詞典裡幾乎不用的。手挑的 `gen_tts.PREFERRED` 合格就優先用。
- 指定換字（`tts_subs.PINNED`，River 聽過或決定的，優先於自動挑選）：不 ㄈㄡˇ→否、幢 ㄔㄨㄤˊ→床、淺 ㄑㄧㄢˇ→遣、得 ㄉㄜˊ→德。
- 照原字唸的例外：
  - 「一」「不」(ㄅㄨˋ)：變調（不是 bú shì、一切 yí qiè）要交給語音，換字會唸錯調。
  - 輕聲（˙）注音：不強制。
  - 找不到單一讀音的同音字、而且注音就是這個字平常的讀音（佛、說、大、法、我、三、女、白…）：送拼音反而風險較大，照原字唸。
  - 這個字實際上只有一個讀音，但同音字只剩很罕用的（頻率不到 1/50，如 來→萊、入→褥、可→坷）：換了反而怪，照原字唸。
- 送數字調拼音（只有 Google 語音會照拼音唸，其他語音照原字唸）：找不到同音字、注音又不是平常讀音的（難 ㄋㄢˋ、橫／行 ㄏㄥˋ、勒 ㄌㄜˋ、血 ㄒㄧㄝˇ、崖 ㄧㄞˊ），
  或舊的詞語預測器認為在這本經裡會唸錯的（更 ㄍㄥˋ「不復更生」）。這幾個在非 Google 語音上仍可能唸錯，`polyphones_review` 列為「高」。
- 聽到唸錯：記下句子。是挑錯同音字的，加到 `tts_subs.PINNED`；是規則漏掉的字，改 `tts_subs.py`。然後重新產生（見下面）。

### 破音字逐處判讀（River 2026-11-20）
- 原則：每一處破音字的注音，都由讀整句、看語意和詞性決定（例如「不」是否定還是「否」、「為」是「是／被」ㄨㄟˊ 還是「替／為了」ㄨㄟˋ、「還」是返回 ㄏㄨㄢˊ）。不靠只看字形的固定規則。
- 判讀紀錄：`tools/readings/decisions/<id>.tsv`，每一處一列：段、行、字的位置、字、判讀的注音、狀態（keep 原注音正確／change 改讀／ask 不確定，照原注音等 River 決定）、原注音、依據、理由、前後各 4 字的上下文。
  建書時核對字和上下文；經文改過、位置對不上就報錯，那幾處要重審。
- 慣用讀音詞庫：`tools/readings/lexicon.tsv`（v1）。是過去判讀的「記憶」：每條有字、注音、朗讀、可省略的前文／後文語境條件、語境說明、例句、理由、來源、範圍。
  只用來建議新經的讀音、檢查前後一致（`readings.py check` 會列出和有語境條件的詞條不一致的地方）；不會自己改注音，每一處仍要人看過。
- 破音字＝教育部注音表或 pypinyin 有兩個以上讀音的字（或注音不是它的任何已知讀音）。2026-11-20 七部經共 9,987 處全部判讀過（祈請文 1,031、心經 178、普門品 1,253、大勢至章 138、阿彌陀經 1,121、藥師經 2,926、金剛經 3,340）；加上經名 44 處，共 10,031 處。
  這次改讀 42 處：答語「不也」12、還 ㄏㄨㄢˊ 9、五百之百 ㄅㄞˇ 4、稱量／不可量之量 ㄌㄧㄤˊ 2、應時 ㄧㄥˋ 1、白佛言之白 ㄅㄞˊ 1；
  另 18 處不確定的由 River 決定（2026-11-20）：唯然 ㄨㄟˇ 2、雨（動詞）ㄩˋ 2、大行 ㄒㄧㄥˊ、盧舍那 ㄕㄜˋ、樂見 ㄧㄠˋ、教人書 ㄐㄧㄠ、空閑 ㄎㄨㄥˋ、一分 ㄈㄣˋ 2、厭媚／厭禱 ㄧㄢˇ 2（改 13），所教 ㄐㄧㄠˋ、名聞 ㄨㄣˋ 2、人身長大 ㄔㄤˊ 2 維持。目前沒有待決（ask）。
- 新經的流程：
  1. 建書工具產生初步注音（`--strict` 先不要加）。
  2. `python3 tools/readings.py sheet <books> <id> --out <id>.review.tsv`：列出所有破音字，詞庫有語境條件符合的會帶建議讀音，狀態 todo。
  3. 逐句讀過，填注音、狀態（keep／change／ask）、依據、理由；存成 `tools/readings/decisions/<id>.tsv`。新的慣用讀音加到 `lexicon.tsv`。
  4. `python3 tools/readings.py check <books> <id>`：todo 0、衝突 0。
  5. 加 `--strict`（或 `READINGS_STRICT=1`）重建：注音套判讀、朗讀表同一步產生。之後才看 `polyphones_review` 的「高」「中」兩區、請 River 試聽。
  6. ask 的那幾處請 River 決定，再改 decisions 重建。

### 「不」讀 ㄈㄡˇ（＝否）（River 2026-11-20）
- 「不」在文法上作「否」時，注音標 ㄈㄡˇ，朗讀換成「否」（River：文法上是否就注音和讀音都改）。現在每一處都記在判讀紀錄裡（依據 `fou-q`、`fou-buye`），不再由建書工具的固定規則決定（`tts_subs.apply_fou()`、`ann.py` 的舊強制規則已停用）。
- 問句句尾（`fou-q`）：普門品「於汝意云何？是善男子、善女人，功德多不？」、藥師經「汝為信不？」、金剛經「寧為多不？」「可以身相見如來不？」等，共 34 處：普門品 1、藥師經 1、金剛經 32。
- 答語「不也」（`fou-buye`）：金剛經「不也，世尊！」12 處（回答前一句「…不？」）。其他六部經沒有。
- 其他「不」都看過：句中否定（「云何菩薩不受福德？」「若逢不逢」「過時不雨難」）仍標本調 ㄅㄨˋ，變調交給語音。大勢至章、祈請文、阿彌陀經、心經沒有作「否」的「不」。
- 語音不會自己把這些「不」唸成 fǒu（一律唸 bù），所以一定要靠注音＋換字。

### 經名也要唸（River 2026-11-20「經名 怎麼都沒唸」）
- 原因：經名和譯者是第一頁版面上的純文字（`reader.js` 直接用 `book.title`／`book.translator` 畫出，沒有注音、也不是經文單位）。朗讀只從經文段落（`blocks`）切句，所以七部經從頭播都直接從經文第一句開始，經名被跳過；朗讀表 `.tts.json` 也只看經文。
- 現在：從第一頁開始朗讀時，先唸經名（第 0 句，經名那一欄淡色標出），接著直接唸經文。點經名也會從經名開始唸。從後面的頁開始唸則照舊從那頁第一句開始。
- 譯者行（「唐 玄奘 譯」「姚秦 鳩摩羅什 譯」等）不唸（River 決定）。
- 經名的注音存在 `book.title_zy`，版面不顯示，只給朗讀用。破音字和經文一樣逐處判讀：`decisions/<id>.tsv` 裡 blk 是 -1 的列就是經名。
  建書工具沒有給 `title_zy` 的書，由 `readings.apply()` 產生：只有一個讀音的字直接用那個讀音，破音字照判讀紀錄，沒有紀錄時 --strict 會失敗。
  `tts_subs.py` 和 `gen_tts.py` 都會把經名算進去，所以經名的破音字一樣換成同音字。
- 七部經經名唸法（跟各經經文的讀法一致）：
  - 祈請文：諸佛菩薩祈請文 ㄓㄨ ㄈㄛˊ ㄆㄨˊ ㄙㄚˋ ㄑㄧˊ ㄑㄧㄥˇ ㄨㄣˊ
  - 心經：般若波羅蜜多心經 ㄅㄛ ㄖㄜˇ ㄅㄛ ㄌㄨㄛˊ ㄇㄧˋ ㄉㄨㄛ ㄒㄧㄣ ㄐㄧㄥ
  - 普門品：妙法蓮華經觀世音菩薩普門品第二十五（沿用普門品注音版的經名注音，華 ㄏㄨㄚˊ、法 ㄈㄚˇ）
  - 大勢至章：大勢至菩薩念佛圓通章 ㄉㄚˋ ㄕˋ ㄓˋ ㄆㄨˊ ㄙㄚˋ ㄋㄧㄢˋ ㄈㄛˊ ㄩㄢˊ ㄊㄨㄥ ㄓㄤ
  - 阿彌陀經：佛說阿彌陀經 ㄈㄛˊ ㄕㄨㄛ ㄚ ㄇㄧˊ ㄊㄨㄛˊ ㄐㄧㄥ（阿 ㄚ，跟本經經文 25 處一致）
  - 藥師經：藥師琉璃光如來本願功德經 ㄧㄠˋ ㄕ ㄌㄧㄡˊ ㄌㄧˊ ㄍㄨㄤ ㄖㄨˊ ㄌㄞˊ ㄅㄣˇ ㄩㄢˋ ㄍㄨㄥ ㄉㄜˊ ㄐㄧㄥ
  - 金剛經：金剛般若波羅蜜經 ㄐㄧㄣ ㄍㄤ ㄅㄛ ㄖㄜˇ ㄅㄛ ㄌㄨㄛˊ ㄇㄧˋ ㄐㄧㄥ
- 經驗：版面上「不是經文」的字，像經名、標題、頁眉，朗讀不會自動包含。新增書或改版面時，要確認哪些字應該唸，並把它們放進朗讀序列和讀音判讀裡。

### 經末也標經名、以經名結尾（River 2026-11-21）
- 七部經的經文最後本來都沒有單獨一行經末題（阿彌陀經、金剛經、藥師經、心經、普門品、大勢至章、祈請文都是直接結束在「信受奉行／咒語／最後一句」）。藥師經末段有「此法門名說藥師琉璃光如來本願功德」，那是敘述，不是經末題，所以七部都在最後加標經名。若未來某部經原文最後一句已是經名（忽略標點後相同），版面和朗讀都不再加第二次。
- 版面：最後一頁（或最後一頁剩下的欄位）用和首頁同樣的大字直書經名欄（`.tcol .tc`），不排譯者。有空位就排在最後一頁既有經文欄的左邊（直書的末尾），不夠就多一頁只放經名；既有經文欄位不重排。
- 朗讀：從頭播完最後一句經文後，再唸一次經名（同一套 `title_zy`／blk -1 的判讀），經末經名欄反白，然後停止並顯示「朗讀完畢」。譯者行不唸。點經末經名會從經名唸起；從最後一頁按朗讀，若該頁還有經文就從該頁第一句開始，若只有經名就從經名開始。
- 不另做 blk -2 判讀列：結尾和開頭是同一段經名、同一套注音。

### 朗讀控制在上方工具列（River 2026-11-21）
- 拿掉會擋住經文的底部浮動控制條（`#tpl`）。暫停／繼續改由上方「▶ 朗讀」鈕本身切換（朗讀中變成「⏸ 暫停」，暫停中變成「▶ 繼續」）；停止、語速、語音選單排在它旁邊（`#tctl`），只在朗讀或暫停時出現。
- 原浮動條沒有「上一句／下一句」按鈕，所以沒有加。
- 裝置全螢幕時，朗讀中仍會留下一條只含播放控制的細工具列，否則沒有暫停／停止可用。
- 全螢幕鈕在 ☰ 目錄旁（經文頁與咒語頁相同）：UA 含 Tesla → 按下才走 `youtube.com/redirect?q=本頁?q=fullscreen#hash`（不自動跳轉）；其他瀏覽器支援 `requestFullscreen` → 進出全螢幕；兩者都不支援就不顯示。右側舊的全螢幕鈕已隱藏。

## 點字朗讀
- 點（或滑鼠按）經文裡任何一個字：沒在唸就從那句開始唸；正在唸或暫停中就跳到那句。
- 翻頁不受影響：這個閱讀頁本來就是用捲動和「上一頁／下一頁」按鈕、鍵盤翻頁，經文上沒有點擊翻頁的區域。手指滑動是捲動，不會觸發朗讀。拖曳選取文字也不會觸發。
- 桌機滑鼠移到字上，游標會變成手指，字底下淡淡變色。

## 經末經名比較小（River 2026-11-23）

## 語速越快，句間停頓越短（River 2026-11-23）
- 瀏覽器在兩句 utterance 之間的空隙，用 `setTimeout` 只能加長、不能縮短，所以不另外插入延遲。
- 1×：切句方式與原來相同（只加上面的引號規則），每句上限 48 字。
- 1.25×：同一句裡的分句（，、；：）合併成較長的一句再送出，句號／驚嘆／問號仍切開；上限 60 字。引擎在句中標點自己停頓，這個停頓會隨語速變短，目標約短 20%。
- 1.5×：同樣合併分句，上限 72 字；若一句很短，可與下一短句合併（不跨標題），目標約短 40%。
- 實測（2026-11-23，盒上 Chrome、Google 國語（臺灣）、心經正文前幾句的 onstart／onend）：句數 1× 67、1.25× 11、1.5× 6。合併後仍切開的句界，引擎空隙約 129／143／221 ms，本身不會隨語速變短（這也是不用 setTimeout 的原因）；省下的停頓改由引擎在句中的，、；：裡自己做出，並隨語速縮小。金剛經正文句數 1048／453／124。
- 換語速時會依新規則重切句，從目前這個單位所在的那一句繼續。點字跳讀、暫停／繼續、反白都對應合併後的那一句。換字表（`from`／`to`／`zy`）在句中留有標點時仍依漢字＋注音對應，不受影響。
